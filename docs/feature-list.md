# 機能一覧

作成日：2026-11-14

## 目的と状態の見方

本書はSmSecure MVPで提供する機能と対象外を一覧化する。機能は未実装の計画を含み、現時点での製品機能を意味しない。

- **一部実装**: Domainの比較処理など、限定したコードとテストがある。
- **検証待ち**: 技術的な前提が確認できるまで、カテゴリ対応や判定を確定しない。
- **計画**: 実装対象だが未実装。
- **対象外**: MVPでは提供しない。

## MVP機能

| ID | 領域 | 機能 | 利用者に提供すること | 状態・条件 |
| --- | --- | --- | --- | --- |
| COL-01 | 収集 | 手動収集 | CLIから端末の自動起動項目を収集する。 | 検証待ち。カテゴリの対応確定後に有効化する。 |
| COL-02 | 収集 | 収集結果の範囲表示 | 要求した範囲、確認できた範囲、未取得・不明の理由を区別して表示する。 | 計画。正常終了だけで完全取得と判断しない。 |
| COL-03 | 収集 | 収集試行の状態管理 | 実行中、成功、失敗、タイムアウト、解析失敗、中断を識別する。 | 計画。生出力や機密値を含めないエラーコードを保存する。 |
| COL-04 | 収集 | カテゴリ単位の有効化 | 検証済みカテゴリのみを収集・比較対象とする。 | 検証待ち。Logon (`l`) は候補だが、確定カテゴリはまだない。 |
| HIS-01 | 履歴 | スナップショット保存 | 成功した収集結果を、ツール・解析・識別ルールの版や実行条件とともに保存する。 | 計画。失敗した試行を成功スナップショットとして扱わない。 |
| CMP-01 | 比較 | 比較基準の選択 | 同じプロファイル、互換なスコープ・実行条件・ルール版の直近成功スナップショットと比較する。 | 計画。互換性不明の場合は比較しない。 |
| CMP-02 | 比較 | 項目の対応付け | 検証済み識別ルールで一意に対応する項目だけを内容比較する。 | 検証待ち。対応付けできない観測は未解決として示す。 |
| CMP-03 | 比較 | 内容差分 | 取得済みの実行先、署名状態、署名者、ハッシュ、許可された引数を比較する。 | 一部実装。Domain比較処理と単体テストあり。収集、保存、基準選択は未実装。 |
| CMP-04 | 比較 | 状態の明示 | 初回観測、追加、削除、変更、比較済み範囲で変更なし・一部未比較、変更なし、比較不能を区別する。 | 一部実装。存在・カバレッジの根拠生成と基準選択は未実装。 |
| CMP-05 | 比較 | 不明値の扱い | 不明同士を一致とせず、比較不能の理由を保持する。異なるハッシュアルゴリズム間ではハッシュ値を比較しない。 | 一部実装。Domainの単体テストあり。 |
| REV-01 | 確認 | 観測の確認記録 | 利用者が特定の観測に確認済み状態と任意のメモを記録する。 | 計画。記録は観測ID単位で一意とし、別観測へ移動しない。 |
| REV-02 | 確認 | 再確認対象の選択 | 同一項目の最新確認記録を使って再確認を支援する。 | 計画。比較可能な対応付けができない場合は比較不能とする。 |
| WEB-01 | Web | ローカル閲覧 | ログインなしでスナップショット、収集範囲、比較結果、確認記録を閲覧する。 | 計画。ループバック限定で待ち受け、LANから接続できないようにする。 |
| WEB-02 | Web | 確認記録の操作 | 項目を確認し、メモを記録する。 | 計画。更新要求にCSRF対策を行い、観測データ自体は変更しない。 |
| SEC-01 | プライバシー | 引数の保存制御 | 既定で引数を保存せず、保存時は毎回の明示的な対話承認を要求する。 | 計画。非対話実行での保存は拒否する。 |
| SEC-02 | プライバシー | 生出力の非保存 | Autorunscの生出力はメモリ内だけで扱い、ログ・例外・一時ファイルに出さない。 | 計画。引数を保存しない場合、その引数や元コマンド由来のハッシュも保存しない。 |
| SEC-03 | DB保護 | 権限と整合性 | DBロールを用途別に分け、制約で不正な状態や参照を防ぐ。 | 計画。通常ロールには観測・確認記録の更新・削除権限を与えない。 |
| SEC-04 | DB保護 | 収集の排他と原子保存 | 収集を排他制御し、成功スナップショットと観測・範囲・試行状態を同一トランザクションで保存する。 | 計画。同一DB接続でロックを保持し、失敗や通信断を成功扱いしない。 |
| SEC-05 | Web保護 | ログインなしのアクセス境界 | ループバック待受、許可Host/Origin検査、更新要求のCSRF対策、キャッシュ抑止を行う。 | 計画。同一OSユーザー権限で動くローカルプロセスは信頼する。外部公開せず、DNSリバインディングも検証する。 |

## MVP対象外

| ID | 対象外機能 | 理由・境界 |
| --- | --- | --- |
| OUT-01 | 項目の有効化、無効化、削除、修復 | 誤操作を避けるため、MVPは読み取りと確認記録に限定する。 |
| OUT-02 | VirusTotalなどの外部照会・外部レピュテーション | 外部通信と追加のデータ開示を避ける。 |
| OUT-03 | Logon以外の未検証カテゴリ | 検証とカテゴリ固有の識別・取得範囲確認が済むまで対応しない。Logon自体も検証ゲートを通過するまでは確定対応にしない。 |
| OUT-04 | 複数利用者・リモート公開・クラウド同期 | MVPは単一利用者のローカル利用を前提とする。 |
| OUT-05 | 脅威判定や安全性の自動評価 | 観測差分だけで安全・危険を断定しない。 |
| OUT-06 | WebからのOSコマンド実行 | Webは保存済みデータの閲覧と確認操作に限定する。 |

## MVPの受け入れ条件

1. 対応カテゴリと取得範囲が明示され、未取得・不明を「変更なし」と誤表示しない。
2. 追加・削除は比較可能な基準、確定した識別、根拠ある存在差分が揃う場合に限る。
3. 不明値、未解決ID、互換性のない基準は比較不能として理由を示す。
4. 失敗・タイムアウト・解析失敗・中断・DB障害が成功として報告されない。
5. 引数保存の既定オフ、生出力の非保存、DB権限制御、ローカルWeb保護をテストで確認する。
6. CLI収集からDB保存、比較、Web表示、確認記録までのエンドツーエンドテストが通る。

DBの論理スキーマと整合性方針は[DB設計](./database-design.md)、画面・DB・動作契機の関係は[シーケンス図](./sequence-diagram.md)、実装順序と各段階のテスト条件は[実装計画](./implementation-plan.md)、収集機能の検証状況は[技術検証メモ](./technical-validation.md)を参照する。
