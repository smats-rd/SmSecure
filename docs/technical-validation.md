## 比較モデル

`src/domain` は取得範囲や識別キーを決めない。内容比較は両観測が同じ確定済み項目IDを持つ場合に限る。既知のフィールド値だけを比較し、不明同士を一致にしない。引数は両観測で取得・保存済みの場合だけ比較し、アルゴリズムが一致しない、または不明なハッシュ値は比較しない。

| 対応付け・存在・内容 | 主状態 |
| --- | --- |
| 対応付け不能 | 比較不能 |
| 比較可能な過去範囲がない | 初回観測 |
| 根拠ある存在差分 | 追加／削除 |
| 両方存在し、比較可能な値に変更あり | 変更。未比較フィールドも併記 |
| 差なし、比較済みと未比較が混在 | 比較済み範囲に変更なし・一部未比較 |
| 全フィールド比較済みで差なし | 変更なし |
| 比較できるフィールドなし、または存在判定不能 | 比較不能 |

現在のDomainは既に判定された存在状態を受け取るだけで、追加・削除や初回の根拠を生成しない。対応付け不能は他の表示より優先する。比較項目は実装済みの実行先、署名状態、署名者、ハッシュアルゴリズム、ハッシュ、引数であり、カテゴリ検証を踏まえて見直す。

基準は同一収集プロファイル、対象ユーザー・スコープ、互換性のある実行条件、同じ識別・解析ルールバージョンを持つ直近の保存済みスナップショットとする。カテゴリ集合の変更を比較できるよう、プロファイルの同一性と要求カテゴリ集合は別に記録し、選択後に共通して比較可能な範囲のみ扱う。対象ユーザー・スコープなどの必要条件が不明なら互換とみなさない。同時刻はIDによる安定した順序で決め、欠けた範囲を古い履歴で補わない。基準選択と範囲判定は未実装。

確認記録は観測IDにつき1件。再確認比較には同一項目の最新確認日時の記録を選び、同時刻はIDで順序を決める。観測をまたいで確認記録を作成・移動しない。対応付け不能の場合は確認済み観測との比較不能とする。再確認判定は未実装。

## DB・トランザクション設計

以下は実装方針であり、スキーマ・権限の適用やDB統合テストは未実施。

- `collection_runs` は開始・終了・状態・機密値を含まないエラーコードと確定済み条件を保持する。実行中、成功、失敗、タイムアウト、解析失敗、中断を区別する。
- `snapshots` は成功した試行に結び付き、時刻、Autorunsc・解析・識別バージョン、プロファイルと実行条件、引数保存方針を保持する。`snapshot_scopes` は要求範囲と確認できた範囲、状態と理由を分ける。
- `items` は検証済み識別ルールに基づくキーを一意にする。`observations` は必ず一つのスナップショットに所属し、未解決の項目IDとその理由を許す。重複観測は上書きしない。`reviews` は必ず観測を参照し、観測IDに一意制約を置く。同時送信時も既存の記録を返す。
- 外部キー、NOT NULL、状態・値の組み合わせのCHECK制約を付ける。引数保存方針が無効なら、取得状態にかかわらず値はNULL。有効なら取得済みは非NULL文字列（空文字列を含む）、取得失敗はNULL。未試行は完了した観測として保存しない。制約をスナップショットの方針にも整合させる具体的方法はマイグレーションで検証する。
- 移行用・収集用・Web用のDBロールを分ける。通常ロールには観測と確認の更新・削除権限を与えず、試行の状態更新など必要な権限だけを付与する。所有者権限とスーパーユーザーは通常利用に使わない。アプリケーションでも観測・確認を更新しない。
- 専用DBセッションで収集用のPostgreSQLセッションレベルアドバイザリロックを取得し、収集・保存の全期間保持する。ロック取得に失敗した後続は終了する。ロック取得後に残存する実行中試行を中断として確定し、新規試行を記録する。
- ロックを保持する**同じ接続**で保存トランザクションを実行し、スナップショット・観測・範囲・試行成功をまとめてコミットする。接続喪失時は子プロセスを停止し、成功確定の処理を続けない。ロック喪失とコミットの競合を統合テストする。
- 保存や実行の失敗は、トランザクションをロールバック後、可能なら機密情報を含まない失敗状態を記録する。DBへ書けなければCLIで明示して失敗終了する。コミット結果が通信断で不明な場合も成功と報告せず、後からDBで確認できるよう試行IDを表示する。既に成功した試行を失敗で上書きしない。
- 生出力はメモリ内でのみ扱い、エラー、例外、汎用ログや一時ファイルに出さない。引数を保存しない方針では、元コマンドや引数のハッシュも保存しない。保存を有効にする実行は、毎回注意文を示して対話的承認を得る。非対話実行は拒否する。

## Web認証の基本案

既存二ツールから流用可能なローカル認証方式が見つからなければ、一利用者のパスワード認証とサーバー管理の不透明なランダムセッションを使う。パスワードはソルト付きの適切なパスワードハッシュで管理し、設定・認証情報はリポジトリ外でACLを制限する。セッションはログイン時に更新し、有効期限とログアウトを設ける。

待受はループバック限定。固定の許可HostとOriginを照合し、更新操作はPOSTとCSRFトークンを要求する。Cookieには `HttpOnly`、`SameSite=Strict` を付け、接続方式に応じた `Secure` の扱いをブラウザーで検証する。応答は必要最小限とし、認証対象・観測詳細にはキャッシュ抑止を適用する。パスワード試行制限、DNSリバインディング、ログインCSRF、特殊文字の表示も実装時に検証する。WebからOSコマンドを起動しない。
