# 実装計画

作成日：2026-11-14

## 目的と前提

Windows端末の自動起動項目を読み取り、観測履歴と比較結果をローカルで確認するMVPを段階的に実装する。項目の変更・削除などの修復操作は対象外とする。

技術検証の結果、現在確定済みの収集カテゴリはない。Autorunsc 14.3の現在ユーザーに対する限定的なRun/RunOnce登録とコマンド文字列の確認結果を、カテゴリ全体の識別安定性、取得完全性、削除判定の根拠に拡張しない。検証結果と未確認事項は[技術検証メモ](./technical-validation.md)を参照する。

## 実装原則

- 収集対象・ユーザー・スコープ・要求カテゴリ・確認できた範囲を区別して記録する。正常終了だけで完全取得とみなさない。
- 検証済みの識別ルールが適用できない観測は未解決として保存し、別項目と推測で結び付けない。重複観測を上書きしない。
- 互換性を確認できない過去観測を比較基準にしない。取得できなかった範囲を古い履歴で補わない。
- 根拠がない追加・削除を表示しない。判定不能は変更なしや削除として扱わない。
- 生出力をファイル・ログ・例外メッセージに出さず、メモリ内だけで解析する。外部照会オプションは使用しない。
- 引数は既定で保存しない。保存を有効にする場合は毎回対話的な明示承認を要求し、非対話実行を拒否する。
- DBの通常ロールに観測・確認記録の更新・削除権限を与えない。WebからOSコマンドを起動しない。

## フェーズ

| フェーズ | 作業 | 完了条件・ゲート |
| --- | --- | --- |
| 0. 収集契約の確定 | Logon候補について昇格・非昇格、同一ユーザーでの比較、登録場所・項目名・重複、引数の表記、欠損・アクセス拒否・部分取得・空結果を検証する。対象バージョンと外部通信の扱いも確認する。 | 対象ユーザーとスコープ、識別ルール、取得範囲を確認する手段、追加・変更・削除を許す条件が文書化される。条件を裏付けられないカテゴリは未対応のままとする。 |
| 1. Domain契約 | [Domainモデル一覧](./domain-model.md)を基準に、観測・存在・カバレッジ・比較基準の型と状態遷移を固める。未解決ID、互換性のない基準、部分取得、初回観測、確認記録の選択をテストする。収集試行・項目の基本型とDB対応するscope契約は実装済み。 | 不明値や判定不能を変更なし・追加・削除に誤分類しない単体テストが通る。現在の比較Domainをこの契約に整合させる。確認記録の再確認選択と存在差分の根拠生成は未実装。 |
| 2. DB・マイグレーション | [DB設計](./database-design.md)に基づき、`collection_runs`、`snapshots`、`snapshot_scopes`、`items`、`observations`、`reviews`を実装する。制約、DBロール、権限、マイグレーションと接続管理を用意する。 | 新規DBへの適用、制約違反、ロール権限をテストする。DBサーバーのバージョン・接続権限を確認し、収集用・移行用・Web用ロールを分離する。 |
| 3. 収集・保存CLI | Autorunscの起動、タイムアウト、中断、出力のメモリ内解析、試行状態記録、単一接続でのアドバイザリロックと保存トランザクションを実装する。CSVパーサーの単体実装済み（Autorunsc起動・DB保存との接続は未実装）。 | 成功・失敗・タイムアウト・解析失敗・中断を区別し、失敗時に部分スナップショットを成功扱いしない。ロック競合、接続喪失、コミット結果不明をDB統合テストで確認する。 |
| 4. カテゴリ別対応 | フェーズ0を通過したカテゴリだけを有効化する。カテゴリ固有の識別・範囲判定を収集アダプターとして実装する。 | 未解決・重複・欠損・対象外を明示し、追加・削除は比較可能な基準と確認済みカバレッジがある場合に限る。未通過カテゴリは取得しても確定比較に使わない。 |
| 5. 比較基準・確認記録 | 同一プロファイル、互換なスコープ・実行条件・ルールバージョンの直近成功スナップショットを選ぶ。確認記録は観測ID単位で一意に保存する。 | カテゴリ集合の変更、同時刻、失敗試行、互換性不明、同時送信をテストし、異なる範囲を比較したり記録を移動したりしない。 |
| 6. ローカルWeb | ログインなしで、観測・比較・確認の最小画面を提供する。 | ループバック限定待受、許可Host/Origin検査、更新操作のCSRF対策、キャッシュ抑止、特殊文字表示を確認する。DNSリバインディングも実ブラウザーで検証する。 |
| 7. MVP受け入れ | CLIからDB保存、比較、Web表示までのエンドツーエンドを確認する。 | 対応カテゴリ、取得範囲、引数保存状態、失敗状態、判定不能理由が利用者に分かる。生出力・引数が禁止条件下でログや一時ファイルに残らず、失敗を成功として報告しない。 |

フェーズ0の結果に依存するカテゴリ別対応（フェーズ4）は、検証ゲートを通過するまで開始しない。一方、フェーズ0の検証とフェーズ1のDomain契約作成は並行して進められる。フェーズ2はDomain契約を確定してから、フェーズ3はフェーズ1・2の契約とDBが揃ってから開始する。フェーズ5以降は表の受け入れ条件を満たした範囲で進める。フェーズ0の検証に昇格操作や端末設定変更が必要な場合は、対象・権限・後片付けを確認してから実施する。

## 初期スコープと保留事項

- 最初の収集候補はAutorunsc 14.3のLogon (`l`) とするが、フェーズ0完了までは対応カテゴリに確定しない。
- DBサーバーが未作成で接続権限も未確認のため、フェーズ2の開始前に実行環境とロール作成手順を確定する。
- Webにログイン、パスワード、セッションは設けない。ローカル端末上の同一ユーザー権限で動くプロセスは信頼境界内とし、LANや外部ネットワークからの接続を受け付けない。
- 引数の保存は既定で無効とする。保存を有効にする画面・CLIの警告文、承認の有効範囲、設定変更時の扱いをフェーズ1までに定める。
- MVPで必要な観測保持期間、DBバックアップ・復元、データ削除の運用方針をフェーズ2開始前に決める。観測データの通常操作による更新・削除禁止は維持する。

## 検証・テスト方針

- Domainは状態遷移と比較規則の単体テストを中心にする。
- Autorunscアダプターは合成CSVでヘッダー差、引用符、改行、非ASCII、欠損列、壊れた行をテストし、実行ファイルを使う検証は承認済みの一時登録に限定する。
- DBは実際のPostgreSQLで制約、権限、ロック、トランザクション、接続断を統合テストする。
- CLIはプロセス終了コード、標準エラー、タイムアウト、出力異常、DB障害それぞれで失敗状態と終了コードを確認する。
- Webは認証なしのローカルアクセス境界、CSRF、Host/Origin、キャッシュ、表示エスケープをテストする。WebリクエストからOSコマンドが起動されないことも確認する。
- 各フェーズで追加した範囲に対応する最小のテストを先に用意し、完了条件を満たすテスト結果を残す。
